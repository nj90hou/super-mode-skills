# super-mode-skills

[English](./README.md) | **中文**

基于公开可观察信息与本地研究整理的 `Doubao Super Mode` 风格 skill 仓库。

本仓库不是豆包官方实现，也不声称复刻其闭源产品形态。它做的是另一件事：把豆包超能模式里最值得借鉴的任务编排思想，收敛成一套可维护、可扩展、可双语发布的 skill 体系。

## 这个仓库是什么

`super-mode-skills` 是一套双语 skill 包，目标是把复杂任务从“单次回答”提升为“完整任务链”：

- 先判断任务模式和复杂度
- 再做任务分解与阶段控制
- 再进入正式研究或自动化执行
- 再生成结构化交付物
- 最后做质量门禁、恢复续跑和结果交付

当前仓库提供两套并行目录：

- `zh-cn/`：中文 skill
- `en/`：英文 skill

两套目录表达的是同一代协议与能力边界。

## 为什么参考豆包超能模式

根据公开页面、公开体验文章和本地调研，豆包超能模式最值得对标的，不只是“会搜索”“会写报告”，而是它把复杂任务做成了一条可观察、可恢复、可产物化的任务链。

从公开信息里，可以较稳定地观察到这些方向：

- 它不是单纯的回答增强，而更接近一层高阶任务代理
- 它强调多轮搜索、深度推理、浏览器操作、文档/网页/PPT 等交付形态的联动
- 它明显重视模式选择、任务执行过程、结果容器，以及某种程度的恢复 / 回放体验
- 它把复杂任务当成“任务系统”而不是“一条更长的 prompt”

本仓库真正借鉴的是这些结构化能力，而不是 UI 外观或闭源实现细节。

## 豆包超能模式公开可观察到的能力

以下内容是基于公开资料做的能力归纳，不代表官方内部完整实现：

### 1. 模式层

公开体验和产品表述反复说明，豆包不是只有一个统一回答模式，而是存在不同复杂度 / 成本 / 深度层级。对复杂任务而言，模式层的意义是：先决定“任务怎么跑”，再决定“调用什么能力”。

本仓库对应实现：

- `fast`
- `think`
- `expert`
- `super`

这些模式会影响：

- 是否允许跳过某些阶段
- 研究预算强度
- 质量门禁强度
- 自动化与恢复能力是否启用

### 2. 统一任务链

豆包超能模式公开描述的核心不是单点能力，而是链路能力：

- 搜索
- 推理
- 浏览器操作
- 产物生成
- 交付

本仓库对应实现：

- 主 skill 统一编排
- 分解、研究、自动化、创作分轨执行
- 通过共享状态对象把各阶段串起来

### 3. 正式研究门禁

公开产品体验里，复杂任务往往不是直接开写，而是先做研究、验证和组织，再进入生成。

本仓库对应实现：

- `recon` 轻量侦察
- 选择式初始澄清
- `research_question` 明确化
- `evidence_pack` 作为进入正式生成的硬门槛
- `validation` 阶段单独存在

### 4. 浏览器与自动化能力

公开描述中，豆包超能模式强调过网页访问、信息收集、页面操作、表单填写等能力。这意味着复杂任务不只停留在“说”，而是进入“做”。

本仓库对应实现：

- `网页自动操作器`
- 自动化子任务中的人工接管点
- 登录 / 授权 / 提交确认的显式暂停机制
- 自动化结果回写到结构化产物对象

### 5. 产物化交付

豆包超能模式公开体验中，高频出现网页、文档、PPT、分享等结果容器。也就是说，最终交付物是系统的一等公民，而不是最后一段长答案。

本仓库对应实现：

- `artifact_registry`
- `target_artifacts`
- 支持 `html` / `docx` / `md` / `xlsx` / `pdf` 等目标格式
- 研究包、草稿、终稿作为不同工件看待

### 6. 恢复与续跑

复杂任务真正难的不是“第一次跑”，而是中断后怎么继续。豆包超能模式公开能力里，恢复、回放、继续执行是重要体验点。

本仓库对应实现：

- `resume_triggered`
- `resume_from_stage`
- `resume_summary`
- `revalidation_needed`
- 已确认澄清 / 已批准计划 / 已完成研究默认不重跑

## 本仓库已经实现了什么

### 主 skill：`超能模式`

主 skill 不只是一个路由器，而是控制平面。它负责：

- 任务模式判定
- 任务轨道识别
- 共享状态维护
- 阶段状态机推进
- 结果门禁检查
- 默认值补全与升级控制
- 恢复执行边界控制

关键实现点：

- v2 共享状态协议
- v1 兼容别名
- `task_graph`
- `evidence_pack`
- `artifact_registry`
- `execution`
- `recovery`
- `quality_gates`
- `decomposition_visibility`

### 子 skill 1：`复杂任务分处理器`

负责把复杂请求拆成结构化任务图，而不是只输出自然语言待办事项。

核心实现：

- 子任务节点化
- 依赖关系
- 完成定义
- fallback 路线
- 关键路径
- 共享状态摘要
- 分解过程可视化摘要
- 统一调整检查点
- 局部重规划

### 子 skill 2：`深度网页搜索`

负责正式研究，而不是仅仅返回几条搜索结果。

核心实现：

- `recon` / `full` 双模式
- 研究分档：`briefing / standard / deep / special-topic`
- 查询预算、深读页数、来源覆盖、交叉验证要求
- `source_matrix`
- `key_findings`
- `conflicting_claims`
- `gaps`
- `confidence`
- `decision_log`
- 研究升级路径

### 子 skill 3：`网页自动操作器`

负责结构化网页操作与自动化结果回写。

核心实现：

- 自动化节点读取
- 页面 / 字段 / 回写目标约束
- 关键步骤状态记录
- 登录 / 授权 / 提交确认的人工接管
- 结构化采集结果
- 截图 / 页面快照等自动化产物回写

### 子 skill 4：`多内容生成器`

负责基于研究包和共享状态生成正式交付物。

核心实现：

- 从 `evidence_pack` 驱动成稿
- 章节和证据映射
- 根据交付类型选择组织结构
- 生成后自审
- 输出结构化产物信息
- 保留局限、冲突与证据缺口，不伪装为完整结论

## 仓库当前能力边界

这个仓库已经实现的是“skill 级任务编排协议”，不是完整产品运行时。

已实现：

- 模式层
- 分解层
- 研究层
- 自动化层
- 创作层
- 证据门禁
- 工件注册
- 恢复续跑语义
- 中英双语版本

尚未等同于豆包官方产品的部分：

- 官方产品级 UI / 插件运行时
- 闭源前端插件体系
- 真实网页画布 / 分享链接 / 回放界面
- 产品级账号灰度和权限控制
- 官方内建模型与运行预算分配逻辑

换句话说，本仓库实现的是“任务编排能力模型”，不是“豆包前端产品复刻”。

## 适合什么场景

这套 skill 更适合：

- 复杂、多步骤、跨阶段任务
- 研究 + 生成
- 自动化 + 生成
- 多交付物任务
- 需要正式证据门禁的报告型任务
- 需要中断恢复的长链任务

## 不适合什么场景

不建议把它当成：

- 轻量闲聊技能
- 单轮快速问答技能
- 完全无结构的小型写作模板
- 官方豆包超能模式一比一复刻项目
